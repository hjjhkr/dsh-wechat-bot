# 交接说明

> 写给接手的人（包括负责实现微信适配器的人）。先读这一份，再按需要读 [protocol.md](protocol.md)、[commands.md](commands.md) 和根目录 [README](../README.md)。

## 1. 一句话现状

**插件逻辑层已完成并通过测试；微信接口层（适配器）需要按 [protocol.md](protocol.md) 重新实现。**
在适配器完成之前，插件默认连接内置**模拟器**，整套功能（初始化、控制台、监听、合批、对象判断、命令、记忆、DSH 会话镜像）都能完整运行和演示。

## 2. 这次重构做了什么

原项目（提交 `85a9ec3` 是重构前的完整快照）把"微信读写"和"机器人逻辑"写在一起：单聊天、强绑定 Python worker、大量为单次事故打的补丁和墓碑测试，消息合批虽然有代码但实际没有生效。重构后：

| 方面 | 之前 | 现在 |
| --- | --- | --- |
| 与微信的边界 | Node 直接驱动特定 Python worker 的私有 RPC | 一份通用 JSON-RPC 协议，适配器可替换；自带模拟器和一致性检查工具 |
| 监听范围 | 一次一个聊天，切换要暂停/回滚 | 任意多个聊天并行，每个聊天内部严格串行 |
| 多条消息 | 合批逻辑未生效 | `Batcher` 合批，整批作为一个 JSON 数组一次交给模型；思考中来新消息会重新考虑（有上限） |
| 说话对象 | 全靠模型从文本里猜 | 程序先算出 `addressed = you/maybe/other/none` 及原因，模型再判断；必须回复时会纠正一次 |
| 回复形式 | 一条消息 | 最多 N 条短消息，按打字节奏发送 |
| 命令 | 无 | `/` 命令运行时 + 发言模式 + 禁言 + 自定义命令脚本 |
| DSH 集成 | 独立 web 实例 + 自建页面 | 普通 DSH 插件：`/wechat` 初始化、右侧栏控制台、`wechat_bot` agent 工具、每个聊天一个原生会话 |
| 锁屏 | 锁屏即暂停相关逻辑分散在多处 | 插件侧完全不依赖桌面；适配器用 `canSend` 声明能否发送，插件排队/过时丢弃 |
| 测试 | 70+ 项，很多是针对历史事故的墓碑测试 | 52 项场景化测试 + 内置模型评测套件 |

## 4. 关键设计决定

1. **"谁在跟谁说话"用事实，不靠猜。** @、引用来自适配器提供的元数据（`mentions`、`quote`），程序据此标注 `addressed`。模型仍然做最终决定，但不用从文本里反推元数据。
2. **整批一次决策。** 每批只调用一次模型，同时产出回复和记忆；没有空轮询调用。
3. **宁可漏发，不可重发。** 只有适配器明确说 `send_failed` 才重试；超时、断线、`send_uncertain` 一律不重试。用 `clientId` 让适配器做幂等。
4. **锁屏 = 能不能发的问题，由适配器声明。** 插件不检测桌面状态，只看 `event/status.canSend`。
5. **身份只认 id，且来自数据。** 发送者、@、引用、记忆归属全按适配器从微信本地数据库读出的 id 判断，昵称和正文都不能改变身份。插件不看聊天界面，也没有"主人"之类的特权身份。
6. **DSH 会话只做展示。** 每个聊天的"微信 · 聊天名"会话是只读镜像（不跑 agent loop、不给模型任何工具），在里面打字会被拒绝并提示。会话 id 由小号 id + 聊天 id 哈希得到，重启后接着用同一个。
7. **初始化绑定到第一次触发的工作区。** `/wechat` 记下该会话的工作区，之后的会话镜像都建在那里，控制台在其他工作区只显示"控制台在 X"。

## 5. 给适配器实现者：要做的事

协议全文见 [protocol.md](protocol.md)。按优先级：

0. **收消息走本地数据库，不看界面**：微信把聊天存在本地（加密的）SQLite 库里，`event/message` 需要的一切——消息 id、发送者 wxid、群成员与群昵称、`@` 列表（消息元数据里的 atuserlist）、引用（被引用消息的 id 和发送者）、表情包/图片的标识——都能从库里直接读出，不需要截图或识别聊天框。只有**发送**必须经过微信客户端（写数据库不会把消息发出去）。
1. **最小可用**：`initialize`、`account/status`、`account/login`、`chats/list`、`watch/set`、`event/message`（文字）、`message/send`（文字）、`shutdown`。
   做到这一步，机器人就能在真实微信里工作。
2. **质量相关**：`mentions`（从消息元数据取，不要从正文猜）、`quote`、`chats/members`、`chats/history`、`event/status`（锁屏/断线时 `canSend:false`）、发送的幂等与失败分类。
3. **体验相关**：`window/get|set`、`event/log`、`qrCode`。
4. **后续功能**：`kind: image/sticker` + `media.description`、`media/fetch`、发送 `image/sticker`。

参考资料：

- **旧实现**：`git show 85a9ec3:plugins/dsh-wechat-bridge/python/...`，以及 `adapters/wechat-windows/`（本次未改动）。旧实现里包含读取本地消息库、群成员与 @ 元数据解析、通过 UI 自动化写草稿并发送、以及按数据库回显确认送达等做法，可以作为起点；但它的进程间协议是旧的私有格式，需要改成本协议。
- **旧会话记录与结论**：`git show 85a9ec3:handoff/2026-10-21/` 下的 `HANDOFF.zh-CN.md` 和 `sessions/`，`_work/*/RESULTS.md`。里面记录了当时验证过/没验证过的东西（例如锁屏下的发送从未真正验收）。
- **一致性检查**：`node plugins/dsh-wechat-bot/bin/check-adapter.js -- <你的命令>`。

实现时需要注意的行为点（来自旧项目的教训）：

- **消息 id 必须稳定**：适配器重启后同一条消息要还是同一个 id，否则插件会把旧消息当新消息回复。
- **发送结果要分三类**：没发出（`send_failed`）/ 可能发出（`send_uncertain`）/ 现在不能发（`unavailable`）。旧项目大量复杂度来自没有把这三种情况分开。
- **回显确认**：能在消息库里看到自己刚发的消息再返回成功，最稳；看不到就返回 `send_uncertain`，不要猜。
- **后台、隐藏、熄屏、锁屏、睡眠是不同状态**，不要把其中一种的验证结果推广到别的状态；锁屏下能否发送需要实测。
- **不要抢用户焦点**：不要用全局键鼠、剪贴板或切换桌面作为兜底。
- **微信版本升级会改变 UI 结构和内部细节**，与版本相关的参数要能重新校准，不要写死。

### 窗口显隐

控制台的开关已经做好，等适配器实现 `window/get|set`（能力 `window: true`）。需求是：**切换时不抢用户前台焦点，隐藏时收发照常**。可以评估的方向（都需要实测，这里只是候选）：

- 小号窗口放在独立桌面上运行（不可见），"显示"时由适配器截取窗口画面传给控制台做只读预览，而不是真的把窗口搬到用户桌面；
- 小号窗口留在普通桌面，用"不激活"的方式移出可视区域 / 移回，并设置不出现在任务栏；
- 无论哪种，都要验证隐藏状态下 UI 自动化和发送仍然可用，以及锁屏下的表现。

## 7. 后续可以做的

- **图片/表情包识别**：在 `chat.js` 的 `#decide` 里，对 `kind: image/sticker` 且适配器支持 `media/fetch` 的消息取回文件，作为图片内容块加入模型消息（需要多模态模型）；或者让适配器直接在 `media.description` 里给出描述（最简单，插件已支持）。
- **表情包发送**：`stickers` 配置已接通，模型可输出 `{"sticker":"名字"}`；适配器实现 `content.kind = "sticker"` 即可。可以再加一个 `/sticker add` 命令收集群里的表情包。
- **主动发言**：`idleMinutes` 已实现，默认关闭；开启前建议先用 `/wechat eval` 和真实群观察。
- **在会话里代发**：目前"微信 · 聊天名"会话只读，可以考虑让人在里面打字直接由小号发出。

## 8. 环境与运维备忘

- 状态目录：`~/.dsh/wechat-bot/`（`bot.json`：初始化信息与监听列表；`chats/<hash>.json`：每个聊天的上下文、记忆、日志、模式）。不要在运行中手改。
- 卸载：DSH 设置 → 插件里移除，或 `dsh plugin --profile desktop remove dsh-wechat-bot`。
- 开发时插件目录下的 `node_modules` 是指向 DSH Desktop 模块目录的 junction（已 gitignore），用于测试解析 `@deepseek-ai/*`；DSH 加载插件时用的是同一份模块。
- 本次验证用的隔离 DSH 实例和数据都在临时目录，已在交接前关闭。
